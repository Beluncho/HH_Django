# Этап 5. Презентация для защиты

Отчёт о подготовке публичного выступления: слайды, план доклада и способ публикации.

## 1. Что сделано

Слайды собраны как **одна самодостаточная HTML-страница** и публикуются через GitHub Pages.

| Что | Где |
|---|---|
| Слайды (20 штук, с заметками докладчика) | [`docs/index.html`](index.html) |
| Схемы и графики слайдов (SVG) | [`docs/img/`](img/) |
| Флаг для GitHub Pages (отключает обработку Jekyll) | [`docs/.nojekyll`](.nojekyll) |
| Отчёт об экспериментах, на который ссылаются слайды | [`docs/stage4_report.md`](stage4_report.md) |

Адрес страницы:

```text
https://beluncho.github.io/HH_Django/
```

**Пока GitHub Pages не включён, адрес не открывается** — включение делает владелец репозитория
руками, см. раздел 3.

## 2. Как листать и что внутри

Открывать страницу можно двумя способами: по адресу выше (нужен интернет) или локально —
двойным щелчком по `docs/index.html` (тоже нужен интернет: библиотека слайдов подгружается с
CDN, см. ограничения в разделе 6).

| Действие | Клавиша |
|---|---|
| Следующий / предыдущий слайд | `→` / `←`, пробел, клик |
| Обзор всех слайдов сеткой | `Esc` |
| Заметки докладчика (тезисы к текущему слайду) | `S` |
| Ссылка на конкретный слайд | адрес страницы + `#/7` |
| Экспорт в PDF | адрес страницы + `?print-pdf`, затем печать → «Сохранить как PDF» |

Заметки докладчика — не текст для чтения вслух, а опорный конспект: главная мысль слайда,
цифры, которые нужно назвать, и что показать рукой. В режиме заметок (`S`) открывается второе
окно — его удобно держать на ноутбуке, а на экран выводить слайды.

## 3. Как опубликовать (один раз, руками)

1. Репозиторий → **Settings** → **Pages**.
2. **Source**: `Deploy from a branch`.
3. **Branch**: `AI_Agents_diploma`, папка **`/docs`** → **Save**.
4. Через минуту-две страница появится по адресу `https://beluncho.github.io/HH_Django/`.

Почему именно так: презентация лежит рядом с отчётами и ссылается на них относительными
ссылками; ветка `main` при этом не меняется, а `docs/.nojekyll` отключает обработку Jekyll,
поэтому файлы отдаются как есть.

### 4.1. Рисунки

Пять слайдов несут схемы и графики отдельными SVG-файлами в [`docs/img/`](img/). Числа на
графиках взяты из сохранённых прогонов [`docs/stage4/`](stage4/), ни одна цифра не нарисована
от руки.

| Файл | Слайд | Что показывает | Откуда числа |
|---|---|---|---|
| `rag-collections.svg` | 7 | что наполняет каждую коллекцию и кому она видна | правила проекта |
| `observability.svg` | 11 | путь сбоя модели до понятной подсказки | код этапа 6 |
| `frequency.svg` | 13 | вакансии против упоминаний для восьми навыков | `experiment_frequency.md` |
| `chunk-size.svg` | 14 | 107 / 68 / 52 фрагмента при 600 / 900 / 1200 символах | `experiment_chunk-size.md` |
| `embedding.svg` | 15 | `hash` даёт три нуля, MiniLM — убывающую шкалу | `experiment_embedding.md` |

SVG выбран вместо картинок: текст внутри остаётся текстом, файл весит единицы килобайт и
масштабируется без потери резкости при экспорте в PDF. Шрифт внутри — системный стек, поэтому
вывод через `?print-pdf` не зависит от того, какие шрифты стоят на машине.

## 5. Что показывать вживую

Порядок на слайде 19; он же в [`demo_map.md`](../demo_map.md), раздел «Команды для показа»:

```bash
./run_local.sh migrate
./run_local.sh check_llm
./run_local.sh run_analysis_demo "Python-разработчик" --area 1
./run_local.sh run_experiment frequency
```

`check_llm` — одна короткая команда, которая подтверждает связь с провайдером до начала показа.
Если модель недоступна, она отвечает человеческой подсказкой («провайдер не обслуживает модель —
проверьте `LLM_MODEL`»), а строка с телом ответа провайдера ложится в журнал; на защите это
лучше, чем выяснить то же самое на середине доклада.

В браузере: вход → `/trainer/` → запрос и регион → таблица навыков → «Объяснить навык» →
«Начать собеседование» → ответ → разбор по рубрике. Затем админка:
`/admin/candidate_trainer/llmrequestlog/` — журнал обращений к модели (сбой виден телом ответа
провайдера) и `/admin/candidate_trainer/knowledgecollection/import/` — загрузка методички в базу
знаний прямо из браузера.

**План Б, если нет сети или токена HH.** Показ на демо-выгрузке: она не требует ни ключей, ни
обращений к HH, потому что карточки вакансий и два объяснения навыков сохранены заранее.

```bash
./run_local.sh loaddata demo_analysis   # вход: demo / demo1234
```

## 6. Ограничения и следующий шаг

1. Библиотека слайдов (`reveal.js`) подгружается с CDN, поэтому страница открывается только при
   наличии интернета. Если для защиты нужна полностью автономная версия, два файла библиотеки
   можно положить в `docs/` и заменить ссылки на локальные — правка на две строки.
2. GitHub Pages включается владельцем репозитория руками (раздел 3); из кода это сделать нельзя.
3. Скриншотов интерфейса в презентации нет — показ идёт вживую, и это осознанное решение.
   Схемы и графики на слайдах при этом есть (раздел 4.1), но это SVG, нарисованные по данным,
   а не снимки экрана: они не устаревают при смене шрифта оформления и весят меньше.
   Если снимки всё же понадобятся, они кладутся в `docs/img/` и вставляются в слайд одной
   строкой `<img>` — правило `.figure` в `index.html` уже задано.
4. Числа на слайдах, в графиках `docs/img/*.svg` и в отчёте взяты из сохранённых прогонов
   [`docs/stage4/`](stage4/) — при повторном прогоне экспериментов значения нужно обновить в
   трёх местах: сырой блок, [`stage4_report.md`](stage4_report.md) и соответствующий SVG.
5. Оформление слайдов повторяет защитную страницу прошлого диплома (ветка `Presentation`):
   тёмный сланец `#0f2027`/`#203a43` и золото `#ffd700` в шапке титульного слайда, белые
   скруглённые карточки с мягкой тенью, чипы стека, тёмные блоки для команд и золотая полоса
   слева от заголовка слайда.
   Одно отличие от исходной страницы: там золото используется и как цвет текста на белом фоне,
   а контраст золота на белом — 1.4:1, то есть ниже порога читаемости. Поэтому на светлых слайдах
   золото оставлено только для заливок (полоса заголовка, круглые номера шагов, шапка таблицы),
   а для текста введён отдельный тёмный акцент `#8a6512` (5.3:1 на белом).
   Тень и скругления не влияют на печать: при экспорте в PDF `data-background-gradient` может
   отпечататься ровным тёмным фоном вместо градиента — на читаемость это не влияет.
