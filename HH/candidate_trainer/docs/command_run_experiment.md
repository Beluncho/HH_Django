# Команда `run_experiment`

Прогон экспериментов для файла этапа 4: сравнение вариантов промтов и параметров поиска
с воспроизводимым выводом.

> Статус: команда реализована и проверена (`tests/test_demo_commands.py`).
> Служебный план работ в git не хранится.

## Назначение

Этап 4 требует файл экспериментов, где каждый вариант описан в отдельном разделе вместе с
результатом и выводом о лучшем варианте. Команда печатает готовый размеченный блок
«параметры → результат», который копируется в этот файл.

## Как запустить

Подготовка окружения (venv, зависимости, `.env.local`) — в разделе «Подготовка окружения»
файла `command_run_analysis_demo.md`, для обеих команд она одинаковая.

```bash
./run_local.sh run_experiment <experiment> [параметры]
```

Напрямую:

```bash
cd HH && python manage.py run_experiment <experiment> [параметры]
```

## Эксперименты

### `frequency` — способ подсчёта частоты

Сравнивает «число вакансий, где встретился навык» против «число упоминаний в тексте».
Считается локально по сохранённым снапшотам, сеть и LLM не нужны.

```bash
./run_local.sh run_experiment frequency --query "Python-разработчик" --area 1
```

### `top-k` — сколько фрагментов забирать из RAG

Меняет `limit` в выборке релевантных фрагментов.

```bash
./run_local.sh run_experiment top-k --query "Python-разработчик" --area 1 --top-k 3,4,6
```

### `embedding` — модель embeddings

Сравнивает `hash` и `sentence_transformers`: для одной фразы-запроса считает близость к
набору тестовых фраз и печатает ранжирование обоих провайдеров. Это микробенчмарк на
фиксированном наборе фраз — он показывает разницу в качестве векторов, но не заменяет
переиндексацию коллекции.

```bash
./run_local.sh run_experiment embedding --query "Python-разработчик" --area 1
```

Второй режим требует установленных `torch` и `sentence-transformers` — команды установки
в разделе «Реальные embeddings» файла `command_run_analysis_demo.md`. Первый вызов
дополнительно скачивает модель (~470 МБ) в `EMBEDDING_CACHE_DIR`.

Если `torch` не установлен, команда не падает: ветка `sentence_transformers` помечается
как недоступная, а в блоке остаётся только ранжирование `hash`. Это удобно для первого
черновика, но для вывода эксперимента нужны обе ветки.

Сравнение в этом эксперименте ничего не переиндексирует. Если после него переключаете
`EMBEDDING_PROVIDER` на `sentence_transformers`, выполните `./run_local.sh reindex_embeddings`
и пересчитайте анализ через `--force` (см. тот же раздел).

### `chunk-size` — разбиение документов на фрагменты

Меняет `max_chars` и `overlap` при делении текста на чанки.

```bash
./run_local.sh run_experiment chunk-size --chunk-size 600,900,1200 --chunk-overlap 120
```

### `prompt-explanation` — варианты промта объяснения навыка

Сравнивает формулировки промта объяснения. **Требует настроенный LLM.**

```bash
./run_local.sh run_experiment prompt-explanation --query "Python-разработчик" --prompt-variant 1,2
```

### `prompt-evaluation` — варианты промта оценки ответа

Сравнивает формулировки рубрики оценки. **Требует настроенный LLM.**

```bash
./run_local.sh run_experiment prompt-evaluation --answer "..." --prompt-variant 1,2
```

## Общие параметры

| Параметр | По умолчанию | Что меняет |
|---|---|---|
| `--query` | — | запрос вакансии, как в `run_analysis_demo` |
| `--area` | `1` | регион, id из `settings.HH_AREA_CHOICES` |
| `--limit` | `HH_ANALYSIS_LIMIT` | число вакансий, 1–20 |
| `--embedding` | `EMBEDDING_PROVIDER` | `hash` или `sentence_transformers` |
| `--top-k` | `5` | сколько фрагментов забирать из RAG (можно список через запятую) |
| `--chunk-size` | `600,900,1200` | размер фрагмента в символах (можно список) |
| `--chunk-overlap` | `120` | перекрытие фрагментов в символах |
| `--prompt-variant` | `1` | номер варианта промта (можно список) |
| `--answer` | — | ответ кандидата для эксперимента `prompt-evaluation` |
| `--out` | не задан — вывод только в консоль | файл для сохранения блока; если указан каталог, имя файла `experiment_<имя>.md` |

## Формат вывода

Блок печатается так, чтобы его можно было вставить в файл экспериментов как отдельный раздел:

```text
=== ЭКСПЕРИМЕНТ: top-k ===
Цель: выбрать количество фрагментов RAG
Запрос: Python-разработчик, регион: Москва
Параметры варианта: top-k=3
Результат:
  <фрагменты / ответы / метрики>
---
Параметры варианта: top-k=4
Результат:
  ...
---
Вывод: лучший вариант — top-k=4, потому что ...
```

## Что нужно для запуска

| Эксперимент | HH API | Embeddings | LLM |
|---|---:|---:|---:|
| `frequency` | только первый прогон | только первый прогон | нет |
| `top-k` | только первый прогон | да | нет |
| `embedding` | нет | да | нет |
| `chunk-size` | только первый прогон | только первый прогон | нет |
| `prompt-explanation` | только первый прогон | да | да |
| `prompt-evaluation` | только первый прогон | да | да |

«Только первый прогон» означает, что командам `frequency`, `top-k`, `chunk-size` и
`prompt-*` нужен готовый анализ запроса и региона. Если он уже выполнен, `run_analysis`
при `force=False` возвращает его из кеша и сеть не используется; при `--force` или на
первом прогоне анализ выполняется заново — с обращением к HH API.

## Связанные настройки `.env.local`

Те же, что у `run_analysis_demo`: `HH_*`, `EMBEDDING_*`, `LLM_*`. Для экспериментов с промтами
обязателен рабочий `LLM_PROVIDER` (не `disabled`) и заполненные `LLM_MODEL`, `LLM_API_URL`,
`LLM_API_KEY`.

Секреты в вывод команды не попадают.
